# 游戏文档菜单 · game-docs-menu

建档案室时，AI 用本菜单向用户**推荐**该项目值得建的设计文档。

## 推荐三原则

1. **按器官不按类型**：不问"你做的是什么类型的游戏"，问"你的游戏有没有下面这些器官"。类型枚举不完，器官就十来个。
2. **空文档是负债**：只建用户**马上要往里写内容**的文档，一次最多 1~2 份。建一堆空骨架只会变成体检报告里的未登记文件。
3. **已有等价物就登记不新建**：用户已经有"设定.txt"，就把它登记进真相源（或协助迁移到模板结构），不另起炉灶。

## 用户要的文档不在菜单上怎么办

菜单是**推荐，不是边界**。用户会要菜单里没有的文档——社区公约、剧情 wiki、媒体包、mod 指南、内部流程文档。这很正常。菜单的存在是帮 AI **推荐**，不是给用户能建什么设限。用户要了菜单外的文档时：

1. **先问一句用途**："这个是拿来做什么的？"——答案决定放哪、要不要套模板。别审讯，问一句就动手。
2. **放对位置**：遵守项目现有的目录结构。游戏设计文档进 `docs/design/`、决策进 `docs/decisions/`、给人看的人口页放根目录。没有合适的文件夹就问用户想放哪——别擅自建新的顶级目录。
3. **不硬套模板**：`templates/game-docs/` 里没有合适的模板，就建一个只有标题和 AI 快读头（一句话 / 当前阶段 / 下一步 / 卡点）的空文档。绝不把不相干的模板硬塞进去。
4. **登记进真相源**：新文档一律登记进 `truth-source.json`，取一个合理的主题 id，和菜单内文档一视同仁。建完跑 `keeper truth check`。
5. **尊重 authority 标注**：如果文档所属领域在分工表里标了归属人（如"世界观归 maru 管"），AI 只组织、只实现——不越界写那个领域的内容。

一句话：**菜单负责推荐，用户负责决定，AI 负责登记和保持整洁。**

## 常备件（几乎所有游戏都值得有）

| 文档 | 一句话 | 模板 |
|------|--------|------|
| 玩法总纲 `game-design.md` | 核心循环：玩家每分钟在干什么、为什么想继续 | [game-design](../templates/game-docs/game-design.template.md) |
| 美术/UI 规范 `art-ui-spec.md` | 定住风格：色板、比例、字体、UI 常用件——防素材越做越跑偏（AI 生成素材的时代尤其重要） | — |
| 代码架构 `architecture.md` | 模块划分 + 数据流向，AI 协作写码的地图 | — |
| 决策记录 `decisions/` | 一事一文，记"为什么当时这么选"（ADR 惯例） | — |

## 器官件（按特征查表）

问用户："你的游戏有没有——"

| 器官 | 有 → 推荐文档 | 说明 |
|------|--------------|------|
| **讲故事**（剧情、结局） | 世界观设定 `world-setting.md` | 基调/规则/历史/禁忌——AI 写文案时的护栏 |
| **有名有姓的角色** | 角色设定 `characters.md` | 角色卡集：定位/性格/说话方式/关系网 |
| **数值成长或经济**（等级、金币、掉率、配方） | 数值与经济 `economy.md` | 资源产出/消耗表 + 增长曲线意图，防通胀失控 |
| **关卡或谜题**（一关一关过） | 关卡设计 `level-design.md` | 关卡节奏表 + 教学曲线（新机制在第几关引入） |
| **多场景/地图自由走动** | 场景设计 `scene-design.md` | 每个场景：画面构成/可交互物/入口出口 |
| **剧情分支或多结局** | 分支流程 `story-flow.md` | 分支树 + 各结局达成条件，防叙事悬空 |
| **联机** | 网络设计 `netcode.md` | 同步策略 + 权威端裁定规则 |
| **自研工具**（编辑器、工坊、配置器） | 工具设计 `tools/<名>.md` | 工具的用户是谁、解决什么重复劳动 |
| **外部素材**（买的/免费的图、音、字体） | 素材来源清单 `asset-sources.md` ⭐ | **法律件**：每个素材记来源/授权协议/署名要求。上架前必查，出事最疼 |

## 单系统设计文档（长期高频件）

游戏做深后最常写的其实是**单系统设计稿**：战斗系统、合成系统、好感度系统、存档系统……每上一个系统一份文档，用统一骨架：[system-design 模板](../templates/game-docs/system-design.template.md)。

命名建议 `docs/design/<系统名>.md`，写完登记进真相源，ROADMAP 对应任务标注 `design: docs/design/<系统名>.md`。

## 推荐话术示例

> 你的游戏有剧情、有角色、玩家在多个场景里走动——建议先建这三份：世界观设定、角色设定、场景设计。另外你提到用了 itch 上买的音效包，强烈建议顺手建一份素材来源清单（上架 Steam 时要查授权，现在记零成本，将来补要命）。玩法总纲可以等核心循环再明朗一点建。先建哪份？

要点：推荐带理由、给优先级、一次不超过 3 份、让用户拍板。
